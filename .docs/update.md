## 2026-09-23 — 同じ操作の巡回を止め、div や li の行も押せるようにする

- 変更:

  - 同じページ（URL）で同じ操作（要素の名前と種類）を、連続していなくても 3 回選んだら、人への引き継ぎか停止に回す。要素の id は読み直しで振り直されるため数える鍵にしない。人が操作して再開したら数え直す。
  - `a`・`button` 以外でも、`onclick`、`tabindex`（0 以上）、指の形のカーソルを持つ要素を押せる行（role は `item`）として読む。ボタンの中の `span` や、リンクを包むだけの要素は二重に数えない。`role=option`・`treeitem`・`checkbox`・`radio`・`switch`、`summary` も読む。
  - 追加修正（ルームに入ってメッセージを入れても送れなかった件）:
    - 文字も `aria-label` も無いアイコンだけのボタンを捨てていた。SVG の `title` を名前に使い、無ければ `id`・`class`・`data-testid` に send/submit があれば「送信（アイコン）」、それ以外は「アイコンのボタン」として読む。
    - 送信ボタンが無く form にも属さない入力欄（Enter で送るチャット欄）は、送信を頼まれていれば承認を経て Enter を押し、送信後の確認を行う。form の中で送信ボタンを決められない欄は従来どおり送らない。
    - 「〜入れて送信」のように「送信」で終わる指示も送信の依頼とみなす。
    - 送信後の結果文は、ボタンと Enter の両方を指す「送信操作をし、…」にした。
  - 追加修正（検索欄に同じ文字列を入れ直し続けた件）: 入力後に欄が空に戻る（Enter で検索、描き直し、別ページから戻る）と、未入力とみなして候補に戻していた。Jev は指示文に書かれた欄を選び直しやすく、履歴を渡しても止まらなかった。このタスクで入力を終えた欄は、名前と種類で覚え、ページや URL が変わっても入力候補に出さない。入力に失敗した欄は入れ直せる。
  - 追加修正（メッセージに入れる文字列を検索欄へ入れた件）: 入力欄を選ぶと、依頼から必ず何か文字列を作って入れていた。文字列を作るときに、依頼にこの欄へ入れる内容があるか（`fits`）も Gemini に判断させ、欄の種類（検索欄など）も渡す。無ければ入力せず、その欄を候補から外し、履歴に「依頼に合う内容が無いため入力しなかった」と残す。キーが無いときは従来どおり依頼から作る。
  - 追加修正（ルームを開いた後のメッセージ入力と送信まで進まなかった件）。模擬チャット（ルーム検索、`div` のルーム行、contenteditable のメッセージ欄、アイコンの送信ボタン）で実際の Jev・Gemini・Playwright を動かして見つけた問題:
    - 要素の名前を `innerText` で読むと、横に並んだ span がつながり「ttest」「営営業部」になり、依頼の語と結び付かなかった。要素の区切りごとに空白を挟んで読む（非表示の子は除く）。
    - 最初のページで「戻る」を選ぶと about:blank に出ていた。通ったページの列を持ち、戻り先があるときだけ「戻る」を候補に出す。
    - 検索欄の横の「検索語をクリア」を送信ボタンと取り違え、押して欄が空いたことを送信完了と報告していた。名前にクリア・キャンセル・削除・閉じるなどを含むボタンは送信ボタンにしない。送信の依頼は検索欄に向けない（検索欄は入力時の Enter で検索済み）。
    - 入力内容の判定を欄の種類ごとの規則にした（検索欄は開く・探す相手の名前だけ、文章の入力欄は欄名が依頼に無くても送る文を入れる）。
