# 変更履歴

## 2026-09-23 — 停止・切断時の後片付けと整合性の見直し

- 背景: 画面の「停止」やタブを閉じて受信が切れると、実行中のループを強制的に止めていた。ブラウザを閉じる処理が走らず、Chrome と専用プロフィールが使用中のまま残り、次の実行が起動に失敗しうる。
- 変更:
  - 受信が途中で終わったときは停止要求だけを出し、ループはブラウザを閉じてから終わる。`BrowserSession.close` は途中で失敗しても Playwright を止める。
  - 指示文のパスワード行はすべて伏せる（従来は最初の 1 行だけ）。短い値は他の文字列を壊さないよう、パスワード行の値だけを伏せる。
  - キー未設定のメッセージを API・CLI・ランナーで共通化した。CLI の `--max-steps` を API と同じ 1〜50 に制限した。
  - 画面: 承認待ちでステータスを「確認待ち」にする。停止後に「停止しました。」を表示する。API エラーの文言を日本語に揃え、422 の detail（配列）も表示できるようにした。ヘッドレスの初期表示を既定値（表示する）に合わせた。
  - README の環境変数は `.env.example` を正本として参照する形にした。
  - `GEMINI_MODEL` の既定値を `.env.example` と同じ `gemini-3.5-flash-lite` に揃えた。
  - アプリ名を `jev-use` に統一した（画面のタイトル・ロゴ、通知の送信元、FastAPI のタイトル、`pyproject.toml` のパッケージ名 `jev-use-backend`、要素の目印 `data-jev-use-id`）。TypeSafe のモデル名としての Jev（`jev/`、`JevAsker`、`jev-latest`、SSE の `jev`）は変えない。
- 影響: API・SSE イベントの形式は変わらない。人の確認・入力の再開には `/api/browser/human-ready/{run_id}` を使う（既存）。
- 検証: `uv run pytest`。

- 変更: ユーザー名とパスワードの入力欄をやめた。ログイン画面と、次の操作を選べないとき・同じ操作を繰り返すときは、開いているブラウザで人が入力し、「続行」でその続きから動く。指示文に書かれたパスワードは、判断と経過には出さない。
- 検証: `uv run pytest`。

## 2026-09-22 — ブラウザ操作へ全面刷新

- 背景: スクリーンショットを見て座標をクリックする Computer Use は、毎ステップの画像往復が待ち時間の大半を占めていた。ブラウザなら DOM からボタンと入力欄が取れる。
- 変更:
  - デスクトップ操作（Gemini Computer Use、pyautogui、画面解析）を廃止した。
  - Playwright がページの操作できる要素を読み、Jev が候補の id を選び、Playwright がその要素をクリックまたは入力する。座標は作らない。
  - スクショは画面のプレビューだけで、判断には渡さない。
  - 入力する文字列と最終回答の文章だけ Gemini のテキスト生成を使う。キーが無いときは指示文とページの抜粋に倒す。
  - 危険度が閾値以上の操作は、承認があるまで実行しない。
- 影響: API は `/api/browser/assess` `/api/browser/run` `/api/browser/stop` `/api/browser/approve`。デスクトップ用の API と設定は使わない。
- 検証: `uv run pytest`。

## 2026-09-21 — Jev の結果判定と次アクション審査を 1 リクエストへ統合

- 背景: Jev（TypeSafe）は 1 リクエストで複数の型付き質問に答えられるが、1 ステップあたり
  `action_gate`（審査）と `outcome_checker`（結果判定）へ直列に 2 回問い合わせていた。
- 変更:
  - `backend/src/app/services/jev/step_review.py` を新設し、`outcome` / `recovery` / `verdict` /
    `progress` の 4 質問を 1 リクエストで問う `StepReviewer` を追加。
  - `desktop_use_agent._run_loop` の順序を変更し、前ステップの結果判定と次アクションの審査を
    次のステップの先頭でまとめて行うようにした（`_review_step`）。
  - 先頭アクションは統合判断の審査結果を使い、2 つ目以降は従来どおり `action_gate` が個別に審査する。
  - 審査が無効・実行済み操作なし・画面状態なし・完了主張のときは結果判定だけを問い、`action_gate` が個別審査する。
- 影響:
  - Jev 往復が 1 ステップあたり最大 2 回から 1 回へ減少。
  - 結果判定が次のステップ先頭になるため、その所見は次の依頼（1 操作後）に添えられる。
    中止・人間確認は次の操作を実行する前に適用されるため、実行される操作の安全性は変わらない。
  - SSE の `outcome` イベントは 1 ステップ遅れて配信される。
- 検証: `uv run pytest`（87 passed）。統合リクエストの質問内容・解釈・フォールバック・
  先頭アクションの審査・安全弁の動作をテストで確認。
